# 두억이와 SQL v0.3.4 다크 모드 — 구현 계획

**목표:** 설정 「화면」(시스템 따라가기·밝게·어둡게)과 어두운 색 「밤의 장터」를 넣는다. 어두운 화면의 대비는 4.5:1 이상이고, 밝은 화면은 v0.3.3과 같아야 한다.

**구조:** 두억이는 리아와 같은 색 이름표를 쓰므로, 리아 v0.19.0의 `theme.js`·머리 스크립트·`tests/contrast.py`를 옮긴다. 색은 `:root[data-theme="dark"]`에서 이름표를 다시 정의해 바꾼다. 밝은 화면이 바뀌지 않았는지는 v0.3.3 코드로 미리 만든 계산된 색 기준과 비교해 확인한다.

**기술:** 바닐라 JS·CSS, esbuild 한 장 빌드(`build.py`), Playwright(Chromium), node:test.

**설계서:** `docs/specs/2026-11-18-다크-모드-설계.md`

## 전체 제약

- 밝은 화면의 계산된 색 차이 0(`contrast.py --theme light --compare` 기준 v0.3.3).
- 어두운 화면 대비 미달 0(`--strict`, 그림 속 장식 글자만 `--skip-art-text`로 빼고 목록 보고).
- CSP: `'unsafe-inline'`·`'unsafe-eval'`·style 속성 금지. 인라인 스크립트는 지문 3개.
- 화면 설정 키는 `dueogi-sql.theme`. 저장(`dueogi-sql-save`)에 넣지 않는다. `saveVer`는 그대로.
- 그림(두억이·의상·배지·좌판·물건·손님·기기 그림)의 색은 바꾸지 않는다. 그림 속 말풍선·글자만 이름표를 따른다.
- 판은 v0.3.4. 커밋 작성자는 `Claude <noreply@anthropic.com>`이고, 꼬리말 두 줄을 붙인다.
- 시험 먼저: 새 기능마다 실패하는 시험을 먼저 보고, 그 출력을 `.superpowers/sdd/v0.3.4/red-*.txt`로 남긴다.

## 검토 초점

1. **SQL 카드와 결과 표의 직접 적은 색:** 흰 카드 위 남색 글자를 어둡게로 바꿀 때 상속 문제가 생기기 쉽다. 이것은 Task 3의 대비 도구가 조립 화면·시트·가게 칸 편집기를 반드시 포함하는 것으로 고정한다.
2. **CSP 지문:** 머리 스크립트를 고치면 지문이 어긋나 배포판이 통째로 멈춘다. 이것은 Task 2의 build_test `test_csp_meta`가 정확한 목록 3개를 검사하는 것으로 고정한다.
3. **번쩍임:** 앱 스크립트에서만 정하면 첫 그림이 밝게 나온다. 이것은 Task 4의 `test_theme_no_flash`로 고정한다.
4. **개발자 모드나 가져오기가 화면 설정을 되돌림:** 이것은 Task 4의 `test_theme_setting_persists`로 고정한다.
5. **좌판 그림 속 말풍선 글자:** SVG 안의 `fill` 직접 값이 대비 도구에서 빠지면 놓친다. 이것은 Task 3에서 `--skip-art-text`로 뺀 목록을 보고하고, 말풍선 글자는 빼지 않는 것으로 고정한다.
