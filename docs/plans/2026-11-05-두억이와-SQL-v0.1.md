# 「두억이와 SQL!」 v0.1 작업 계획서

> **실행하는 에이전트에게:** 필수 하위 기술 superpowers:subagent-driven-development(추천) 또는 superpowers:executing-plans로 작업을 하나씩 실행한다. 단계는 체크박스(`- [ ]`)로 표시한다.

**목표:** 리아와 파이썬! v0.9를 바탕으로, 두억이가 도깨비 장터 데이터로 SQL 17장(85레슨)을 카드 조립으로 가르치는 휴대폰 학습 웹앱 v0.1을 만든다.

**구조:** 리아 저장소를 복사해 Python 실행기(Pyodide)를 SQL 실행기(sql.js 작업자)로, 「직접 작성」을 「카드 조립」으로, 리아를 두억이로 바꾼다. 채점은 조립한 SQL과 정답 SQL을 같은 장터 데이터베이스에서 실행해 결과 표를 비교한다. 레슨 점검기는 Node로 옮겨 모든 정답을 실제로 실행해 본다.

**기술:** 브라우저 JS(ES 모듈, esbuild로 한 장 묶기), sql.js 1.15.2(SQLite 3.54.0, MIT), Node `node --test`, Python 3 + Playwright Chromium(브라우저 시험·빌드), 서비스 워커(오프라인).

**설계서:** `docs/specs/2026-11-05-두억이와-SQL-설계.md` (줄여서 「설계」, §번호로 가리킴)

## 검토 초점

시험이 놓치기 쉬운데 실제 사용자가 가장 먼저 부딪칠 다섯 가지. 각 줄의 시험은 맡은 작업 안에 들어 있다.

1. **조인 조건을 빠뜨린 조립**(예: `FROM orders, order_items`, 약 72만 행)을 실행하면 화면이 멈추지 않고 3초 안에 끝나거나 「너무 오래 걸려요」로 끝나야 한다. 표는 앞 50행만 그린다 → 작업 3 `crossJoinFinishes`, 작업 6 `table caps at 50 rows`
2. **실행기를 못 받았을 때**(첫 실행이 오프라인이거나 wasm 받기 실패) 카드 조립 화면은 「실행기 준비 중/오프라인」을 보여 주고, 터치 문제는 계속 풀려야 한다 → 작업 6 `build item without engine`
3. **헷갈림 카드로 바꿔 끼워도 정답이 되는 문제**(예: 데이터상 `>`와 `>=` 결과가 같음)가 있으면 학습자는 「틀린 줄 알았는데 맞았다」를 겪는다 → 작업 8 규칙 `swap-extra`
4. **정렬 없는 비교에서 `NULL`·숫자·글자가 섞인 행**도 같은 결과면 정답, 행 개수가 다르면 오답이어야 한다 → 작업 4 `unordered compare with NULLs and duplicates`
5. **리아와 같은 주소에서 저장·캐시가 섞임**: 두억이 앱을 쓴 뒤에도 리아 저장이 그대로 있어야 하고, 그 반대도 마찬가지다 → 작업 1 `all storage keys start with dueogi-`, 작업 16 `sw deletes only dueogi- caches`
