# 「두억이와 SQL!」 v0.4 계획서 — 심화 7~12장

**목표:** 7~12장에 심화 레슨 18개(`7-A1`~`12-A3`)를 넣는다.

**구조:** 심화 엔진(열림·보상·배지)과 점검기의 심화 검사(`ADVANCED`, `ADVANCED_GRAMMAR`)는 v0.2에 이미 있다. 이번 판의 일은 네 가지다.
1. 디딤돌 조사로 주제를 확정한다.
2. 점검기에 「뒷장 모양 금지」 검사를 더한다.
3. 장마다 심화 3레슨을 쓴다(7~9장, 10~12장 두 묶음).
4. 화면·문서 일을 한다.

**기술:** ESM JS(node:test), sql.js 1.15.2, Python 3와 Playwright Chromium, esbuild(`build.py`).

**설계서:** `docs/specs/2026-11-18-심화-7-12장-설계.md`. 이것이 이어받는 것은 `docs/specs/2026-11-06-심화-1-6장-설계.md`, 쓰기 안내 `docs/lesson-writing-guide.md`의 심화 절, 본보기 디딤돌 문서 `docs/specs/2026-11-06-심화-1-6장-디딤돌.md`이다.

## 전체 제약

- A1·A2는 그 장 주제를 더 깊게 다룬다. A3는 장터 의뢰다. 읽기 SQL만 쓰고, 타자 없이 카드만 쓴다.
- 레슨 id는 `N-A1`~`N-A3`이고 장 파일의 `ADVANCED` 목록에 넣는다. 장마다 정확히 3개다.
- 레슨 크기·문제 수·조립 수는 본 과정 같은 장과 같다. 카드 더미는 12장 이하다.
- 낱말 범위: N장 심화는 `GRAMMAR[1..N]` + `ADVANCED_GRAMMAR[N]`이다. 13장 이후 모양(`WITH`, `FROM (SELECT`, `UNION`, `OVER`, 날짜 함수)은 쓰지 않는다.
- R36(「이 장터에서는」), R31(「N엽전」), R35(빈칸·빈자리), R13(동점 순서), R48(남는 카드)을 지킨다.
- 숫자와 이름은 `data/market.sql`로 실행해 확인한 것만 쓴다. 민속 사실은 주장하지 않는다. 다른 저장소의 문제를 베끼지 않는다.
- 커밋 작성자는 `Claude <noreply@anthropic.com>`이고 꼬리말 두 줄을 붙인다. 판은 `v0.4`다.
- 다크 모드(v0.3.4) 대비와 CSP는 지금 그대로 지킨다.

## 검토 초점

1. **본 과정 그 장에서 이미 가르친 것과 겹침.** 예를 들어 10-4 「세 표 잇기와 매출」이 이미 JOIN+GROUP BY를 가르쳤을 수 있다. 이것은 Task 1 디딤돌 조사의 「본 과정 위치」 칸에서 판정하고, 겹치면 바꾼 주제를 LOG에 적는다.
2. **SQLite 정수 나눗셈**(`SUM(x) / COUNT(*)`)과 `AVG`의 차이. 이것은 「이 장터에서는」으로 감싼다. Task 2의 7-A2 문제의 정답 결과로 확인한다.
3. **상관 서브쿼리·셀프 조인의 동점과 순서.** 이것은 점검기의 동점 순서 검사가 잡는다. Task 3의 `--full` 통과로 확인한다.
4. **배지 「깊이 파는 사람」의 기준이 18→36으로 늘어남.** 이미 받은 배지는 그대로여야 한다. 이것은 Task 4의 단위 시험 `deep badge kept after more advanced`로 확인한다.
5. **장 파일이 커져 오프라인 저장본·첫 HTML이 커짐.** 이것은 Task 4에서 build_test 크기 한도 통과를 보고 LOG에 기록한다.
