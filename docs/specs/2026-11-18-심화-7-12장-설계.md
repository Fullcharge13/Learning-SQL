## 1. 목표와 범위

**목표**: 7~12장(집계·묶기·CASE와 함수·JOIN·LEFT JOIN·서브쿼리) 장 평가를 통과한 학습자가 원하면 그 장을 한 걸음 더 깊게 익혀요. 장터 데이터로 실제 의뢰 같은 문제도 풀어 봐요.

**성공 기준**
- 본 과정만 끝낸 학습자가 각 장 A1을 처음 카드로 풀 수 있어요(디딤돌 조사와 내용 검토로 확인).
- `node tests/content.js --full 17`에서 본 과정 85 + 심화 36의 문제점이 0이에요.
- 심화를 건너뛴 학습자의 지금 레슨·하루 목표·과정 완주는 v0.3.4와 같아요.
- 레슨만 하는 학습자의 하루 엽전 중앙값은 40~50 그대로예요.

## 2. 주제 표 (초안)

본 과정 조사(2026-11-18, 장 파일에서 SQL 모양을 셈)로 고른 빈 곳이에요.
- 두 열 묶기: 11장에서 처음 나와요.
- 집계로 줄 세우기: 14장에서 처음 나와요.
- `SUM(CASE …)`: 17장에서 처음 나와요.
- `GROUP BY CASE`·셀프 조인·상관 서브쿼리·SELECT 줄 안 서브쿼리: 본 과정에 없어요.
- `FROM (SELECT …)`: 13장 내용이라 12장 심화에서는 쓰지 않아요.

| 장 | A1 | A2 | A3 (장터 의뢰) |
|---|---|---|---|
| 7 모아 세기 | 집계 안에서 계산하기(`SUM(price * stock)` = 재고 값어치) | 집계끼리 계산하기(`MAX(price) - MIN(price)` 값의 폭, `SUM / COUNT`와 `AVG` 견주기; ROUND는 9장이라 쓰지 않음) | 「장터 한 줄 요약」: 물건 수·평균 값·가장 비싼 값을 한 줄로 |
| 8 묶어서 세기 | 두 열로 묶기(`GROUP BY shop_id, category` 같은 모양) | 집계로 줄 세우기(`ORDER BY COUNT(*) DESC`)와 HAVING 조건 둘 | 「가게별 성적표」 |
| 9 값 바꿔 보기 | CASE로 조건 세기(`SUM(CASE WHEN … THEN 1 ELSE 0 END)`) | CASE로 만든 갈래로 묶기(`GROUP BY CASE …`) | 「가격대 안내판」: 싼·보통·비싼 갈래마다 물건 수 |
| 10 표 잇기 ① | 같은 표 두 번 잇기(셀프 조인, 별칭 둘). 데이터에 맞는 예가 없으면 「ON에 조건 더하기」로 바꿈 | 잇고 묶기(JOIN + GROUP BY, 10-4와 겹치면 「잇고 HAVING으로 거르기」) | 「단골 영수증」 |
| 11 표 잇기 ② | LEFT JOIN과 CASE로 「있음·없음」 표시 | LEFT JOIN을 잇달아 할 때 짝 없는 행이 사라지는 함정(11-4와 겹치면 바꿈) | 「한 번도 안 팔린 물건 목록」 |
| 12 질문 속 질문 | 바깥 행마다 다시 묻는 서브쿼리(상관 서브쿼리: 「자기 가게 평균보다 비싼 물건」) | SELECT 줄 안의 서브쿼리(값 하나를 열로) | 「평균보다 자주 오는 손님 찾기」 |

## 3. 레슨 규칙 (v0.2 설계 §3에 더할 것)

- 카드 크기: 본 과정 같은 장의 카드 덩어리 규칙(R38~R47)을 따라요. 9장부터 CASE 한 갈래, 12장 서브쿼리 여는·닫는 덩어리.
- A3도 A1·A2를 했다고 기대하지 않아요. A3가 A1·A2 모양을 쓰면 A3 첫 카드에서 다시 짧게 보여 줘요(v0.2 디딤돌 §0과 같음).
- 엔진마다 다른 동작은 「이 장터에서는」으로 감싸요(R36). 예: 정수 나눗셈(`SUM / COUNT`), `CASE` 없이 참·거짓을 더하는 SQLite만의 방식은 가르치지 않음.
- 숫자·이름은 `data/market.sql`로 실행해 확인한 것만 써요.

## 4. 만드는 방법

v0.2 설계 §4와 같아요.

4. **점검기와 화면**: 이미 있는 심화 검사가 그대로 적용돼요. 장 파일이 커지므로 장 파일 크기와 첫 HTML 크기를 기록해요.

## 5. 검증

- **내용**: `node tests/content.js --full 17` → 심화 36레슨 문제점 0.
- **단위**: 심화 7~12장에 13장 이후 낱말·모양(`WITH`·`FROM (SELECT`·`OVER`)이 들어가면 점검기가 잡아요. 이것은 시험으로 심어 확인해요.
- **화면**: `tests/flow.py`에 시험을 추가해요. 7장 평가를 통과한 저장으로 7-A1을 풀어요. 12장까지 통과한 저장으로 홈 학습 길의 심화 별 18개(7~12장)와 캡션을 확인해요.
- **경제**: `node tests/sim/economy.js` 레슨만 하는 학습자 40~50, `--advanced`는 참고값으로 봐요.
- **내용 검토** 두 번(7~9장, 10~12장): 본 과정만 한 학습자가 풀 수 있는지, 설명이 맞는지, 데이터 사실이 맞는지 봐요.
- **기본 묶음 전부**와 다크 모드 대비 시험(`contrast.py --theme dark --strict`)을 돌려요. 심화 별이 늘어난 화면도 넣어요.
- **실기기**: 확인 목록 49~50(7장 심화 하나 풀기, 12장 학습 길 별).
