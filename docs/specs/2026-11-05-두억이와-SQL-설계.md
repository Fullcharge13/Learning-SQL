## 3. 화면 (아이폰 세로 기준)

리아와 같은 흐름이다: 시작 → 홈(오늘의 도전 · 오늘의 퀘스트 · 17장 학습 길) → 레슨(두억이 설명 카드 → 문제) → 레슨 완료 → 의상실 · 배지 · 설정.

| 화면 | 바뀌는 점 |

| 설명 카드 | 코드 대신 SQL 한 덩어리와 **그 실행 결과 표**를 보여 준다. 표는 앱이 SQL을 실행해 그린다(손으로 쓴 표 없음) |

| 상단 바 | 바이트 자리에 **엽전** |

## 4. 레슨 데이터와 채점

### 4-1. 레슨 표 형식

리아의 형식(`data/lessons/chN.js`, `CHAPTER`·`LESSONS`, 레슨마다 `id`·`title`·`goal`·`summary`·`cards`·`items`)을 그대로 쓴다. 바뀌는 칸:

- 설명 카드: `code`·`out` 대신 `sql`. 결과 표는 실행해서 그린다.
- 문제 종류: `choice`(객관식), `blank`(빈칸), `order`(순서 맞추기), `check`(확인), **`build`(카드 조립, 리아의 `write`를 대신함)**.
- `choice`의 보기가 결과 표일 때는 보기마다 `sql`을 적고, 앱이 실행해 작은 표로 그린다.
- `blank`의 빈칸 채우기도 보기를 누르는 방식이다(리아와 같음).

`build` 문제의 칸:

| 칸 | 뜻 |
|---|---|
| `q` | 과제 문장 (예: 「나이가 300살 넘는 손님의 이름을 보여 줘」) |
| `cards` | 정답 카드 목록, **정답 순서대로**. 이어 붙이면 정답 SQL이 된다 |
| `extra` | 헷갈리게 하는 카드 2~4개 |
| `need` | (선택) 꼭 써야 하는 카드. 예: 10장 조인 문제에서 `["JOIN"]` |
| `tables` | 「쓸 표 보기」에 보일 표 이름 |

카드 더미는 `cards`와 `extra`를 섞어 보여 준다. 섞는 순서는 문제 id를 씨앗으로 하는 의사 난수(같은 문제는 늘 같은 순서)로 정한다.

### 4-2. 터치 문제

리아와 같다. 결과 표가 들어가는 객관식이 많아지는 것만 다르다.

### 4-3. 카드 조립

- 카드 더미의 카드를 누르면 조립 줄 끝에 붙고, 조립 줄의 카드를 누르면 더미로 돌아간다.
- 「실행」: 지금 조립한 SQL을 실행해 결과 표를 보이거나 두억이가 오류를 설명한다. 횟수 제한 없음, 채점에 영향 없음.
- 「제출」: §4-4로 채점한다.
- 카드 크기: 1~5장은 낱말 하나가 카드 하나. 뒤로 갈수록 덩어리 카드(예: `OVER (PARTITION BY shop_id`)를 써서 **카드 수(cards + extra)는 12장 이하**.
- 카드 글자는 SQL 그대로이고, 표·열 이름 카드에는 작은 한글 뜻을 아래에 붙인다(`name` / 이름).

### 4-4. 채점

1. 조립한 카드를 공백 하나로 이어 SQL을 만든다.
2. 실행한다. 오류면 오답이고, 오류 설명을 보여 준다.
3. 정답 SQL(`cards`를 이은 것)의 결과와 비교한다.
   - 열 개수와 열 이름(대소문자 무시)이 같아야 한다.
   - 값은 같은 형태로 맞춰 비교한다: 실수는 소수 넷째 자리에서 반올림, `NULL`은 `NULL`끼리만 같다.
   - 행 순서는 정답 SQL에 `ORDER BY`가 있을 때만 본다. 없으면 행을 정렬한 뒤 비교한다(같은 행이 여러 번 나오는 개수까지 맞아야 함).
4. `need`의 카드를 모두 썼는지 본다. 결과가 맞아도 빠졌으면 「결과는 맞았는데 이번엔 ○○를 써 보자」라고 알려 주고 오답으로 친다.
5. 틀렸을 때는 내가 만든 결과 표와 기대 결과 표를 나란히 보여 준다.

조회만 허용한다: 실행기는 `SELECT` 또는 `WITH`로 시작하는 문장 하나만 받는다. 카드로는 다른 문장을 만들 수 없지만 실행기에서도 한 번 더 막는다.

### 4-5. 힌트와 정답

리아처럼 4단계다: ① 무엇을 생각할지 한 문장 → ② 필요한 SQL 낱말 → ③ 정답의 절반 카드를 놓아 줌 → ④ 다음 카드 하나를 대신 놓아 줌(반복 가능). 힌트를 쓰면 「힌트 없이 통과」 퀘스트·배지 집계에서 빠진다.

### 4-6. 오류 설명

`data/errors.js`에 SQLite 오류 문장의 앞부분(예: `no such column`, `no such table`, `misuse of aggregate`, `near "...": syntax error`, `ambiguous column name`)과 두억이 말투의 한국어 설명을 짝지은 표를 둔다. 표에 없는 오류는 「SQL 문장 어딘가가 어긋났어. 카드 순서를 다시 살펴볼까?」로 대신한다. 탐정 의상을 입으면 탐정 말투 설명으로 바뀐다(리아의 탐험가 말투와 같은 구조).

## 5. 도깨비 장터 데이터

### 5-1. 표

모든 레슨이 같은 데이터베이스 하나를 쓴다. 표·열 이름은 영어, 화면에는 한글 뜻을 함께 보인다(D10).

| 표 (뜻) | 열 (뜻) | 크기 |
|---|---|---|
| `shops` (가게) | `shop_id` 가게 번호, `name` 이름, `owner` 주인, `category` 종류(먹거리·약재·잡화·공방), `opened_on` 연 날 | 8 |
| `items` (물건) | `item_id` 물건 번호, `shop_id` 가게 번호, `name` 이름, `price` 값(엽전), `stock` 재고 | 40 |
| `customers` (손님) | `customer_id` 손님 번호, `name` 이름, `kind` 종류(도깨비·사람·여우 등), `age` 나이, `village` 사는 마을, `first_visit` 첫 방문일 | 60 |
| `orders` (주문) | `order_id` 주문 번호, `customer_id` 손님 번호, `ordered_on` 주문 날짜, `status` 상태(완료·취소) | 약 600 |
| `order_items` (주문 내역) | `order_id` 주문 번호, `item_id` 물건 번호, `qty` 수량 | 약 1,200 |

- 날짜는 `YYYY-MM-DD` 글자로 저장한다(SQLite 날짜 함수가 바로 읽는 형태). 기간은 1년(2026-01-01 ~ 2026-12-31).
- `NULL`을 일부러 넣는다: 나이를 모르는 손님 5명 안팎, 재고 칸이 빈 물건 몇 개, 아직 주문이 없는 손님·팔린 적 없는 물건 몇 개(11장 「짝 없는 행」용).

### 5-2. 만드는 방법

- `tools/gen_market.js`가 고정 씨앗의 의사 난수로 데이터를 만들어 `data/market.sql`(표 만들기 + 넣기 문장)로 쓴다. 앱은 시작할 때 이 문장을 실행기에 한 번 넣는다.
- 몇 번을 돌려도 같은 파일이 나와야 한다(§10의 데이터 시험이 확인).
- 분석할 거리를 일부러 심는다. 시험이 각 무늬가 실제로 나오는지 확인한다.
  - 약재 가게 매출은 6~8월이 다른 달보다 높다.
  - 3월에 처음 온 손님은 다른 달 첫 손님보다 재방문율이 높다.
  - 공방(방망이)은 건수는 적고 한 건 금액이 크다.
  - 12월에 주문이 몰린다.

### 5-3. 고증

도깨비 종류·이름과 두억이 이름의 바탕인 「두억시니」는 구현 때 한국민족문화대백과사전·한국민속문학사전 등에서 확인하고, 확인한 항목과 날짜를 `data/market` 생성 스크립트 주석과 README 「고증 출처」에 적는다. 출처를 확인하지 못한 설명은 쓰지 않는다. 실존 인물·특정 종교를 비하하는 이름이나 설명은 쓰지 않는다.

## 6. 커리큘럼 (17장 × 5레슨)

| 장 | 제목 | 배우는 것 | 장터 예 |
|---|---|---|---|
| 1 | 장터 장부 펼치기 | 표·행·열, `SELECT * FROM` | 가게 목록 전부 보기 |
| 2 | 원하는 칸만 | 열 고르기, `AS`, 계산 열 | 값 두 배로 올린 가격표 |
| 3 | 조건으로 거르기 | `WHERE`, 비교 연산, 글자 값 | 엽전 100냥 넘는 물건 |
| 4 | 여러 조건 | `AND`·`OR`·`NOT`, `IN`, `BETWEEN`, `LIKE` | 이름에 「방망이」가 든 물건 |
| 5 | 줄 세우기 | `ORDER BY`, `LIMIT`, `DISTINCT` | 가장 비싼 물건 5개 |
| 6 | 빈칸 다루기 | `NULL`, `IS NULL`, `COALESCE` | 나이 모르는 손님 |
| 7 | 모아 세기 | `COUNT`·`SUM`·`AVG`·`MIN`·`MAX` | 장터 전체 매출 |
| 8 | 묶어서 세기 | `GROUP BY`, `HAVING` | 가게별 매출, 1만 냥 넘는 가게 |
| 9 | 값 바꿔 보기 | `CASE WHEN`, 글자·숫자 함수(`ROUND`, `LENGTH`, `UPPER`, `\|\|`) | 값으로 싼/보통/비싼 나누기 |
| 10 | 표 잇기 ① | `INNER JOIN` | 주문에 손님 이름 붙이기 |
| 11 | 표 잇기 ② | `LEFT JOIN`, 여러 표 잇기, 짝 없는 행 | 한 번도 안 산 손님 |
| 12 | 질문 속 질문 | 서브쿼리(`IN (SELECT …)`, 값 하나 서브쿼리) | 평균보다 비싼 물건 |
| 13 | 중간 표 만들기 | `WITH`, `FROM` 안 서브쿼리, `UNION` | 가게별 합계로 다시 순위 |
| 14 | 줄마다 순위 | `ROW_NUMBER`·`RANK`·`DENSE_RANK`, `PARTITION BY` | 가게마다 가장 잘 팔린 물건 |
| 15 | 누적과 이웃 줄 | `SUM() OVER (ORDER BY …)`, `LAG`·`LEAD`, 이동 평균 | 손님별 누적 구매액 |
| 16 | 날짜와 시계열 | `date()`·`strftime()`, 월별 묶기, 지난달 대비 | 월별 매출과 증감률 |
| 17 | 장터 분석 실전 | 코호트 재방문율, 함께 산 물건, 종합 문제 | 3월 첫 손님의 재방문율 |

- 참고: 데이터 참고 저장소 `cybergeekgyan/SQL-for-Data-Scientists`의 주제 목차와 `krishnaik06/The-Grand-Complete-Data-Science-Materials`의 MySQL 면접 문제 **유형**(N번째로 비싼 것, 중복 찾기, 그룹마다 1등, 중앙값)을 반영했다. 두 저장소의 문장·문제·데이터는 옮기지 않고 모두 새로 쓴다(앞 저장소의 교재 PDF는 무단 복제본이라 열지 않음, 뒤 저장소는 GPL-2).
- 16장에는 「MySQL·PostgreSQL에서는 날짜를 이렇게 다룬다」 비교 카드(보기 전용)를 넣는다. 나머지 장의 문법은 세 데이터베이스에서 같다.
- 장마다 끝에 「실무에서는 이 표가 쇼핑몰의 ○○표에 해당해요」 한 줄을 둔다.
- **배운 문법만 쓴다**: 장마다 쓸 수 있는 SQL 낱말 목록(`data/grammar.js`)을 두고, 그 장까지 배운 낱말만 레슨에 나오게 한다(§10이 막음).
- 레슨당 문제 12개 안팎, 그중 `build` 1~3개. 앞 장은 `build`가 적고 뒤로 갈수록 많다.

리아 v0.9의 규칙과 수치를 그대로 쓴다(XP, 하루 목표 10·20·30 XP, 보호권 최대 2개, 일일 퀘스트 3개 뽑기와 보물상자, 매일 도전 하루 3문제, 장 평가, 레슨 이어 하기). 바뀌는 것만 적는다.

| 항목 | 바뀌는 점 |
|---|---|
| 화폐 | 바이트 → **엽전**. 버는 양·의상 값은 리아와 같은 수치에서 시작하고 §10의 경제 시뮬레이션으로 확인 |
| 퀘스트 6종 | 「오류 난 코드를 고쳐서 통과」 → 「오류가 난 조립을 고쳐서 통과」, 「힌트 없이 코드 통과」 → 「힌트 없이 카드 조립 통과」. 나머지 그대로 |
| 배지 | 「첫 출력」 → 「첫 조회」, 장 완료 배지는 1~3장 대신 **장 이름 단위 묶음**(1~5장 「장부 읽기」, 6~9장 「셈 도깨비」, 10~13장 「조인 장인」, 14~17장 「분석 도깨비」), 「오류 해결사」·「힌트 없이 10회」·「완벽주의자」·「복습왕」·「의상 수집가」·「밤 공부」·연속 7/30/100일·심화 2개는 그대로 |
| 매일 도전 | 문제 틀을 SQL용으로 새로 만든다: 끝낸 장의 터치 문제 2 + 끝낸 레슨의 카드 조립 1 |
| 심화 | 엔진(장 평가 뒤 별 가지, 선택, 보상)은 넣되 레슨이 없는 장에서는 가지를 보이지 않는다 |

## 8. 두억이

### 8-1. 설정

- 도깨비 장터에 사는 꼬마 도깨비. 장부 셈이 특기인 척하지만 사실 배우는 중이라 학습자와 함께 성장한다.
- 말투: 반말 섞인 친근한 해요체("이거 봐요, 엽전이 딱 맞잖아!"). 틀려도 혼내지 않는다.
- 대사 표 `data/lines.js`: 리아와 같은 상황 목록(인사, 정답, 연속 정답, 오답, 실행 중, 오류, 힌트, 레슨 완료, 기록 갱신, 기록 끊김, 의상 구매, 오랜만의 접속)마다 3~5줄, 같은 대사 연속 금지.

### 8-2. 그리기

- `src/dueogi.js`에서 SVG로 그린다(D3). 2~2.5등신 꼬마 체형.
- 살릴 특징: 파란 피부와 붉은 볼, 굵은 뿔 둘, 크게 헝클어진 검은 머리, 붉은 코, 아래 송곳니, 뾰족한 귀, 해진 베 저고리와 털 조끼, 새끼줄 허리띠, 회색 바지와 발목 감발, 짚신, 가시 방망이, 도깨비불.
- 첨부 시트의 그림을 그대로 베끼지 않고 특징을 살려 새로 그린다. 원본 그림 파일은 저장소에 넣지 않는다.

### 8-3. 표정 12가지

| 시트의 표정 | 쓰는 곳 |
|---|---|
| 의기양양(방망이 멤) | 기본, 홈 |
| 만세 + 보라 도깨비불 | 정답, 레슨 완료 |
| 윙크(혀 내밂) | 연속 정답, 실수 없는 레슨 |
| 웃음(눈 감음) | 퀘스트·배지 얻음 |
| 고민(턱 굄, ?) | 힌트, 설명 카드 |
| 놀람(파란 도깨비불) | 오답, SQL 오류 |
| 땀 흘리며 달리기 | 같은 문제 두 번 틀림 |
| 긴장(방망이 쥐고 떪) | 장 평가 시작 |
| 결의(방망이 휘두름) | 장 평가 통과 |

## 9. 저장

- `localStorage` 칸 이름 `dueogi-sql-save` (리아와 겹치지 않게). `saveVer: 1`.
- 상태 항목은 리아와 같고 `bytes` 대신 `yeopjeon`.
- 옮기기 함수 틀(`migrate`)은 처음부터 두고, 깨진 저장은 백업 칸에 남긴 뒤 새로 시작한다(리아와 같음).

## 11. 파일 구성

리아 v0.9 구조를 따른다. 바뀌는 파일만 적는다.

```
src/sqlrun.js        sql.js 작업자 시작·실행·시간 초과 (pyrun.js 대신)
src/worker.js        sql.js를 돌리는 작업자
src/grade.js         결과 표 비교 채점 (§4-4)
src/ui/build.js      카드 조립 화면 (ui/write.js·editor.js 대신)
src/ui/table.js      결과 표 그리기
src/dueogi.js        두억이 SVG (ria.js 대신)
data/lessons/ch1~17  레슨 표
data/grammar.js      장마다 쓸 수 있는 SQL 낱말
data/errors.js       SQLite 오류 → 두억이 설명
data/market.sql      장터 데이터 (tools/gen_market.js가 만듦)
tools/gen_market.js  장터 데이터 생성
tools/dueogi_sheet.py 두억이 그림 시트 PNG
```

라이선스: sql.js 1.15.2(MIT, SQLite 3.54.0은 퍼블릭 도메인)를 `licenses.txt`에 고지한다. 리아 저장소의 코드는 같은 사용자의 것이다.
