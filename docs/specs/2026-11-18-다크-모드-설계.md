## 1. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
1. 설정 「화면」에서 시스템 따라가기(기본)·밝게·어둡게를 고름. 시스템 따라가기는 앱이 켜진 채 휴대폰 설정이 바뀌어도 바로 따라감.
2. 앱을 처음 그리는 순간부터 고른 색으로 보임(밝게 번쩍임 없음).
3. 어두운 화면의 모든 글자와 바탕의 대비가 **4.5:1 이상**(큰 글씨 24px 이상·굵은 19px 이상은 3:1 이상). 자동 시험으로 확인.
4. 밝은 화면은 v0.3.3과 같음. 계산된 색 값으로 비교해 차이 0.

**하지 않을 것**
- 두억이·의상·배지 그림, 좌판·물건 그림, 앱 아이콘의 어두운 버전.
- 레슨·문제·가게 규칙 변경, `saveVer` 변경.
- 매니페스트 두 벌(홈 화면 앱의 시작 그림·상태 표시줄은 알려진 한계).

**실패로 볼 것**
- 어두운 화면에서 안 보이는 글자·단추(대비 미달), 또는 상속 문제(예: 밝은 칸 위의 밝은 글자).
- 앱을 열 때 밝게 한 번 번쩍임.
- 밝은 화면이 바뀜.
- CSP 위반 1건이라도, 또는 첫 HTML 650KB 한도 초과.

## 2. 설계

### 2-1. 저장과 적용 (K2·K4·K6)

- `src/theme.js`(새, 리아와 같은 꼴):
  - `THEME_KEY = "dueogi-sql.theme"`, `THEME_COLOR = { light: "#FBF6EA", dark: <어둡게 --paper> }`
  - `getTheme()`: 없거나 이상한 값이거나 저장소를 못 읽으면 `"system"`
  - `resolvedTheme()`: `system`이면 `matchMedia("(prefers-color-scheme: dark)")`를 따름
  - `applyTheme()`: `<html data-theme>`, `style.colorScheme`, `<meta name="theme-color">`를 맞춤
  - `setTheme(v)`: 저장한 뒤 적용(저장을 못 해도 이번 화면은 바뀜)
  - `watchSystem()`: `system`일 때만 바뀐 시스템 설정을 따름
- `src/index.html` `<head>`의 스타일 앞에 같은 규칙의 아주 작은 인라인 스크립트(`<!-- RIA:THEME -->` 자리)를 둠. 이 스크립트는 `<html data-theme>`와 `colorScheme`만 정함. build의 CSP 지문 목록에 들어가야 함(인라인 스크립트 3개).
- `tools/dev.py`(CSP 없는 개발판)에서도 같은 스크립트가 돎.
- 개발자 모드·가져오기·튜토리얼 다시 보기는 화면 설정을 건드리지 않음.

### 2-2. 색 「밤의 장터」 (K1·K5)

- `:root`(밝게)는 지금 값 그대로. `:root[data-theme="dark"]`에서 같은 이름표를 다시 정의함. 시작 값은 리아 v0.19.0의 최종 값이고, 대비 시험이 통과할 때까지 만드는 사람이 다듬음.

| 이름표 | 밝게 | 어둡게(시작 값) |
|---|---|---|
| `--paper` | #FBF6EA | #141C2B |
| `--paper-2` | #F2E9D5 | #1B2538 |
| `--card` | #FFFDF8 | #1E2940 |
| `--line` | #E2D6BD | #34425E |
| `--ink` | #22304A | #F1EBDD |
| `--ink-2` | #555F72 | #B7BFCD |
| `--teal*` · `--sun*` · `--coral*` | 그대로 | `*-soft`는 어두운 색조, `*-ink`는 밝은 색조(리아 값) |
| `--navy`(코드 상자·띠) | #1F2B3D | #0E1522 |

- 모눈 무늬(`body` 배경 `rgba(34,48,74,.045)`)는 어둡게에서 밝은 선(`rgba(241,235,221,.04)` 근처)으로 바꿈.
- **직접 적은 색**(`#fff`, `rgba(...)` 등, `src/style.css` 약 60곳, `src/ui/*.js` 일부)은 이름표로 바꾸거나 `[data-theme="dark"]` 아래에 어둡게 값을 덧붙임. 밝게 값은 그대로 둠.
- 어둡게 전용 채움 이름표가 필요하면 리아처럼 따로 둠(`--teal-fill`·`--coral-fill`·`--on-sun`·`--muted-ink`).
- **그림과 글자의 경계**:
  - 그림은 그대로: 두억이 몸·의상(`src/dueogi.js`), 배지 그림, 좌판·물건·손님 그림(`src/ui/stallart.js`), 설치 안내의 기기 그림.
  - 글자는 이름표를 따름: 그림 속 말풍선·글자·이름표. SVG 속성에 `var(--card)` 같은 CSS 변수를 씀. 밝게는 같은 값이라 픽셀이 그대로임.
  - 짙은 윤곽선이 밤 바탕 위에서 어떻게 보이는지는 실기기 확인 항목으로 둠.
- 꼭 포함할 화면:
  - SQL 카드(조립 줄·카드 더미·숫자 카드 −/+)
  - 결과 표·「쓸 표 보기」 시트·비교 표
  - 오류·안내 패널
  - 진행 막대
  - 아래 메뉴(잠김·점)
  - 알림(되돌리기 단추 포함)
  - 확인 창
  - 학습 길(노드·별·심화 캡션)
  - 완료 화면의 상태 표시줄 띠
  - 개발자 모드 띠
  - 튜토리얼 카드
  - 가게(정산·장부·의뢰 게시판·칸 목록·칸 편집기·말풍선)
  - 설치 안내
  - 매일 도전

### 2-3. 설정 「화면」 (K3)

- 자리: 첫 묶음(소리·하루 목표·이름) 다음, 「사용법 다시 보기」 앞에 둠.
- 구성:
  - 제목 「화면」
  - 설명 「밤에는 어두운 화면이 눈이 편해요」
  - `role="radiogroup"` 안에 단추 세 개. 각 단추는 `aria-checked`를 쓰고, 화살표 키로 옮겨 다닐 수 있음
- 단추를 누르면 `setTheme`이 바로 적용됨. 알림은 띄우지 않음.

## 3. 시험

1. **단위** `tests/unit/theme.test.js`
   - 값이 없거나 잘못되면 system으로 봄.
   - `setTheme`이 저장하고, `resolvedTheme`이 `matchMedia`를 따름.
   - 저장소를 못 써도 오류 없이 적용됨.
   - 머리 스크립트와 `theme.js`가 같은 결과를 냄(같은 입력 표로 확인).
2. **대비 도구** `tests/contrast.py`(리아 것을 옮김)
   - 대상: 주요 화면 전부를 아이폰 17 크기로 열어 봄. 인사, 튜토리얼 4장, 홈(심화 갈래 포함), 레슨의 고르기·빈칸·순서·조립·오류·결과·완료, 「쓸 표 보기」 시트, 복습, 매일 도전, 배지, 의상실, 설정(설치 안내·확인 창), 가게(입구 잠김·장 열기 정산·의뢰·칸 편집기·시험 실행 결과·비우기 알림), 개발자 모드 띠.
   - 방법: 보이는 글자 요소마다 글자색과 실제 바탕색(조상 중 첫 불투명 배경)의 대비를 잼.
   - `--theme dark --strict`: 미달 0건이어야 함. 그림 속 장식 글자는 `--skip-art-text`로 빼고, 뺀 것은 목록으로 보고함.
   - `--theme light --compare tests/fixtures/contrast-light-baseline.json`: **v0.3.3 코드로 먼저 만든** 기준과 계산된 색 값 차이가 0이어야 함.
3. **화면 시험** `tests/flow.py`
   - 어둡게 저장으로 열 때 첫 그림 시점의 `html[data-theme]`가 `dark`이고 `body` 배경이 어두운 색.
   - 시스템 따라가기: `emulate_media(color_scheme)`를 바꾸면 켜진 채로 따라감. 밝게·어둡게로 고정하면 따라가지 않음.
   - 설정 세 단추: 누르면 바로 바뀌고, 새로 고침·개발자 모드 켜기와 끄기·저장 가져오기 뒤에도 유지됨.
   - 어둡게로 배포판(CSP)을 열어 첫 레슨과 가게 하루를 돌렸을 때 CSP 위반 0.
4. **빌드 시험**: CSP `script-src` 지문이 인라인 스크립트 3개와 정확히 같음. 머리 스크립트가 스타일보다 앞에 있음.
5. **기본 묶음 전부**: npm, content, engine, build_test, flow(건너뜀 0), economy, stall, stall_requests, readme `--check`, pytest.
6. **크기**: 첫 HTML 증가가 6KB 이하로 예상됨. 결과를 일지에 적음.

## 4. 알려진 한계 (실기기 확인 항목)

- 홈 화면 앱의 시작 그림(매니페스트 `background_color`)과 iOS 상태 표시줄 모양은 운영체제가 정적으로 정함. 그래서 어둡게여도 열 때 크림색 시작 그림이 잠깐 보일 수 있음.
- 사파리에서 시스템 설정 변화를 따라가는지, 밤 바탕에서 두억이 윤곽선이 어떻게 보이는지는 실기기 확인 목록 46~48에 넣음.
